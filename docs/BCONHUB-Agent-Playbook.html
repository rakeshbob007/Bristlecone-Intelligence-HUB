Why this matters

Most "AI automation" demos quietly assume an LLM call in the runtime loop — which means a bill that scales with usage. This one doesn't: the AI's job ended the moment the code was written. 04 — Why it's a reusable agent

Not a one-off script — a swappable pattern

"Agent" here means something specific: it observes (scrapes), decides (categorizes), and acts (publishes) on its own schedule, without a human in the loop. What makes it reusable is that every one of those three steps is decoupled from "Bristlecone" and "Mahindra" specifically.

Decoupled data layer

Each source is one small fetcher function returning the same shape: title, URL, date, source name. Point a fetcher at a different company's newsroom URL and the rest of the pipeline doesn't change.

Decoupled rules layer

KEYWORD_RULES is a plain list of (category, keywords) pairs. Retarget the agent to a different industry by editing a list, not rewriting logic.

Decoupled presentation layer

report-template.html only knows about {{PLACEHOLDER}} tokens — it has no idea what company or category set is filling it in.

Decoupled schedule

The GitHub Actions workflow is generic CI/CD — the cron trigger, push trigger, and commit-back step would work unchanged for any repo running any generator script.

In practice

To reuse this for a different organization, you would: (1) write new fetcher functions for its official pages, (2) adjust the category list and keywords if needed, (3) swap the branding in the template's header. Nothing about the scheduling, the placeholder-filling logic, or the CI/CD wiring needs to change. That's the difference between "a script that scrapes Mahindra news" and "an agent framework that happens to be configured for Mahindra news."

05 — Scheduling CI/CD in the Actions tab

Three ways this pipeline starts itself

The workflow lives at .github/workflows/generate-report.yml and is visible under the repo's Actions tab. It's configured with three triggers, so the report is never more than a day — or one relevant commit — out of date.

# .github/workflows/generate-report.yml
on:
  schedule:
    - cron: '0 3 * * *'   # 03:00 UTC = 08:30 IST, every day
  push:
    branches: [main]
    paths:                 # only these changes re-trigger a run
      - 'report-template.html'
      - 'Instructions.md'
      - 'scripts/**'
      - '.github/workflows/generate-report.yml'
  workflow_dispatch: {}    # manual "Run workflow" button
1

Scheduled (cron)

Runs automatically every day at 08:30 IST, whether or not anything else has changed — this is what keeps the report from ever going stale.

on.schedule.cron
2

On relevant push

Fires the moment I push a change to the template, the rulebook, or the script — so a design or logic update shows up in a fresh report immediately, not tomorrow.

on.push.paths
3

Manual dispatch

A "Run workflow" button appears directly in the Actions tab for on-demand runs — useful right after a change, without waiting for the schedule.

on.workflow_dispatch

One deliberate detail: the push trigger's paths list does not include Reports/**. That's what stops the workflow's own commit (which only touches Reports/) from triggering itself in an infinite loop.

06 — Project overview

What BCONHUB actually is

BCONHUB Intelligence Report is a single self-contained HTML report that tells any Bristlecone or Mahindra Group employee "what happened while you were away" — grouped into 8 categories, with real dates and real source links, generated automatically every day at zero cost.

The repository has four moving parts:

Instructions.md

The rulebook: approved sources, the 8 categories, the placeholder contract, and the quality checklist every report must pass.

report-template.html

The reusable design — dark, animated, mobile-friendly, with client-side time filtering and category navigation already built in.

scripts/generate_report.py

The free automation: scrapes 4 real sources, categorizes with keyword rules, fills the template, saves the file — no AI in the runtime loop.

.github/workflows/generate-report.yml

The scheduler: runs the script daily and on relevant pushes, then commits the result back to the repo automatically.

07 — Functional flow

From trigger to published report

Every run — scheduled, pushed, or manual — walks the same five stages.

01

Trigger fires

Cron clock hits 03:00 UTC, or a relevant file is pushed, or someone clicks "Run workflow."

02

Scrape 4 official sources

Fetch the last 60 days of items from Mahindra's newsroom, Mahindra Finance, and two Bristlecone news categories — plain HTTP requests, no headless browser.

03

Categorize

Each item's title is matched against keyword rules to land in 1 of 8 categories — deterministic, no AI call.

04

Render

Fill every {{PLACEHOLDER}} in report-template.html — cards, category counts, the Top Story, the executive summary.

05

Ship

Save as Reports/BCONHUB-Report_<date>_<time>.html, then github-actions[bot] commits and pushes it — live, with zero human involvement.

09 — Strict instructions

The rules every report must obey

All defined in Instructions.md — the same rulebook a human, an AI, and the automated script all follow.

  • 01

    Official sources only

    Every item must come from an approved domain — Bristlecone, the Mahindra family, official LinkedIn, or BSE/NSE filings — with a working, matching link.

  • 02

    Two time windows, never conflated

    Gather from the last 60 days (so the report always has real content), but each item keeps its true date so the reader can filter to the last 24 or 48 hours.

  • 03

    No fabricated content, ever

    An empty category renders an honest empty-state — content is never invented to avoid a blank section. This is the exact rule that ruled out auto.mahindra.com.

  • 04

    A fixed placeholder contract

    Every generator — human, AI, or script — fills the same named {{PLACEHOLDER}} tokens, so the design and the data stay fully decoupled.

  • 05

    Eight fixed categories

    Achievements, Offers & Benefits, Announcements, Financial, Events & CSR, Industry & Innovation, People & Leadership, Trending.
